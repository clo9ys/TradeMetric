# TradeMetric: backend

Команды установки, запуска PostgreSQL, миграций, API, демонстрации и тестов находятся в [корневом README](../README.md). Рабочая папка для Python-команд — `backend`; настройки читаются из `.env` в корне репозитория.

## Выбор источника

| Переменная | Значение и назначение |
|---|---|
| `BOND_DATA_SOURCE` | `csv` (по умолчанию) либо `cbonds` |
| `CSV_DATA_MODE` | `demo` (по умолчанию, источник снимков `demo`) либо `market` (источник `csv`) |
| `CSV_BONDS_PATH` | По умолчанию `backend/data/bonds_demo.csv`; относительный путь считается от корня репозитория, абсолютный тоже разрешён |
| `CBONDS_LOGIN`, `CBONDS_PASSWORD` | Нужны только при выборе Cbonds |
| `PROVIDER_TIMEOUT_SECONDS` | Таймаут HTTP-запросов Cbonds и ЦБ, по умолчанию 10 секунд |
| `DEMO_MODE` | Включает локальные `/api/demo/*`, по умолчанию `false` |
| `CSV_REQUIRE_MANIFEST` | Для активной выгрузки MOEX — `true`: проверяет дату фактической загрузки, SHA-256, число выпусков и даты котировок по соседнему `.meta.json` |
| `DEMO_LAST_TRADING_DATE` | Явная дата учебных котировок для демо API; пример — `2026-11-19` |

`build_bond_provider` возвращает адаптер и ожидаемый источник. `MarketDataService` использует общий `BondDataProvider.get_bond(isin)`. Cbonds сохранён для будущего подключения. RuData не реализован; при ошибке выбранного адаптера переключения на другой нет.

## Формат CSV

Активный рыночный файл: [data/bonds_market.csv](data/bonds_market.csv). Он содержит 100 реальных рублёвых флоатеров MOEX ISS и три фиксированных выпуска CNY. Прежний [data/bonds_demo.csv](data/bonds_demo.csv) остаётся только отдельным синтетическим примером и сейчас не выбран в `.env`. Кодировка UTF-8, BOM допустим; разделитель — запятая. Десятичный разделитель в числах — точка, без разделителей тысяч. Даты записывайте как `YYYY-MM-DD`, без времени. Окружающие пробелы ячеек удаляются; ISIN приводится к верхнему регистру и проверяется по контрольной цифре. Валюта должна быть в верхнем регистре.

Все заголовки из первых 15 строк таблицы обязательны, даже если конкретная ячейка может быть пустой. Последние три колонки можно полностью опустить. Неизвестные колонки и повторные заголовки считаются ошибкой, чтобы опечатка не пропала незаметно.

| Колонка | Значение, единица и обязательность |
|---|---|
| `isin` | ISIN из 12 символов с корректной контрольной цифрой; обязателен |
| `currency` | Трёхбуквенный код валюты облигации: RUB, USD, CNY и т. п.; обязателен |
| `nominal_per_bond` | Непогашенный номинал одной облигации в её валюте, положительный `Decimal`; обязателен |
| `quote_kind` | `percent` — проценты номинала, `amount` — деньги за одну облигацию; обязателен |
| `quote_value` | Положительная котировка в единице, заданной `quote_kind`; обязательна |
| `price_type` | `clean` — без НКД, `dirty` — уже с НКД; обязателен |
| `quote_source` | Реальное происхождение котировки или явная метка учебных данных; обязателен. Не влияет на выбор адаптера |
| `quote_as_of_date` | Дата котировки, должна точно равняться переданному `last_trading_date`; обязательна |
| `coupon_type` | `fixed` либо `floating`; обязателен |
| `accrued_per_bond` | НКД в валюте облигации за одну бумагу, неотрицательный `Decimal`; обязателен для `clean` |
| `accrued_as_of_date` | Дата НКД; обязательна вместе с суммой НКД, не позже даты расчёта |
| `coupon_frequency` | Целое число купонных выплат за год (1..32767); обязательно для `floating`, может быть пустым для `fixed` |
| `modified_duration` | Модифицированная дюрация, годы, неотрицательный `Decimal`; обязательна для `fixed` |
| `convexity` | Выпуклость в согласованной с формулой нормировке (годы²), `Decimal`; обязательна для `fixed` |
| `risk_as_of_date` | Дата дюрации и выпуклости, для `fixed` точно равна `last_trading_date`; обязательна для `fixed` |
| `issue_name` | Необязательное название выпуска |
| `issuer_name` | Необязательное название эмитента |
| `provider_instrument_id` | Необязательный внешний идентификатор выпуска |

Время загрузки `fetched_at` формируется при чтении CSV, это отдельное поле снимка БД. Колонки рыночных дат не заменяются временем чтения. Источник `demo`/`csv` задаётся конфигурацией, а не произвольным полем файла. Для `dirty` НКД и его дата могут быть пустыми; если они указаны, должны быть указаны вместе, но в цену повторно не добавляются. Для `floating` риск-параметры можно оставить пустыми: расчёт использует `1 / coupon_frequency` и `0`.

Поведение при ошибках:

- Отсутствующий в корректном файле ISIN → `InstrumentNotFoundError` с ISIN.
- Повторный ISIN в CSV, включая совпадение после нормализации → ошибка всего файла; выбор первой/последней записи не выполняется. Повторы во входных сделках разрешены.
- Неправильное число, бесконечность/NaN, пустое обязательное поле, неверная дата или неполная строка → `IncompleteMarketDataError`; для ошибки строки указывается её номер, для ошибки преобразования — колонка.
- CSV проверяется целиком при первом обращении к экземпляру адаптера. Ошибка даже в другой строке не позволяет использовать файл частично. Внутри экземпляра прочитанный набор неизменяем; API создаёт новый адаптер на запрос, а БД-кэш может повторно использовать подходящий снимок.
- Файл отсутствует, недоступен или имеет неверную кодировку → `ProviderUnavailableError`.
- Полный, но устаревший снимок → `StaleMarketDataError` в сервисе, до сохранения расчёта.
- Учебные даты не переписываются автоматически. Смена пути CSV не инвалидирует подходящий снимок того же источника за тот же день; кэш разделён по источнику/режиму, а не по пути файла.

## Даты и кэш

Дата расчёта определяется по времени начала запроса в `Europe/Moscow` (UTC+3). Пригодный снимок должен быть загружен в эту московскую дату. Котировка и риск-параметры `fixed` должны точно соответствовать `last_trading_date`, который передаёт вызывающий код. Торгового календаря в приложении нет: автоматически считать любой будний день торговым нельзя.

Существующее правило НКД сохранено: сумма и дата указываются вместе; для `clean` нужны обе; дата не позже даты расчёта. Проверки нижней границы или равенства дате котировки **нет**. Поэтому даже старый НКД может формально пройти проверку. Это ограничение текущей политики: данные НКД должен проверять поставщик/автор CSV, сервис не пересчитывает его на текущую дату. Для более строгой политики потребуется отдельно согласовать дату оценки/расчётов и купонный календарь.

`MarketDataService.prepare_snapshots` ищет дневные снимки в БД, отбрасывает другой источник и повторно проверяет полноту и даты. Только отсутствующие пригодные ISIN запрашиваются у адаптера. `demo`, `csv`, `cbonds` изолированы друг от друга. Более новый непригодный снимок не мешает найти более старый пригодный снимок того же дня. `dict.fromkeys` обеспечивает один запрос на уникальный ISIN без объединения строк сделок.

`prepare_snapshots` не пишет в БД: новые снимки сохраняет `CalculationService` в общей транзакции. Самостоятельный метод `resolve_snapshots` может сохранять только облигационные снимки отдельной короткой транзакцией.

## Цена и DV01

```text
price = nominal_per_bond × quote_value / 100  при quote_kind=percent
price = quote_value                           при quote_kind=amount
dirty_price = price + accrued_per_bond        при price_type=clean
dirty_price = price                           при price_type=dirty
CurrentFairValueRUB = quantity × dirty_price × FX
fixed:    Dmod = modified_duration, Convexity = convexity
floating: Dmod = 1 / coupon_frequency, Convexity = 0
DV01 = CurrentFairValueRUB × (−Dmod × 0.0001 + 0.5 × Convexity × 0.0001²)
TotalDV01 = алгебраическая сумма DV01 строк
```

Все величины обрабатываются через `Decimal`, создаваемый из текста CSV/XML. Промежуточных `quantize`/округлений до копеек нет. Деление, например `1/3`, использует стандартную точность контекста `Decimal` (28 значащих цифр). PostgreSQL `Numeric` не задаёт фиксированное число знаков после запятой. Денежные значения API сериализуются строками.

## Валюты и хранение

Существующий `CBRRateAdapter` расширен, второй адаптер не создавался. Он выполняет GET `https://www.cbr.ru/scripts/XML_daily.asp?date_req=DD/MM/YYYY`; формат запроса описан в [документации Банка России](https://www.cbr.ru/development/sxml/).

Для RUB курс = 1, источник `RUB`, дата действия = дата расчёта; HTTP не выполняется. Для остальных валют используется `Value / Nominal` из XML: при `Nominal=10` и `Value=110` одна единица стоит 11 RUB. Источник — `CBR`, дата действия — `ValCurs.Date`, время получения — реальное время ответа. В выходной допускается возвращённая ЦБ более ранняя дата действия; будущая дата запрещена. Произвольный старый курс из БД не выбирается: адаптер спрашивает именно дату расчёта. HTTP/таймаут, невалидный XML, отсутствующая валюта, неположительные или неконечные Value/Nominal дают `FXRateUnavailableError`.

Миграция `0006` создаёт `fx_rate_snapshots`:

| Поле | Значение |
|---|---|
| `id` | UUID снимка |
| `currency` | Код исходной валюты |
| `rub_per_unit` | RUB за одну единицу валюты |
| `effective_date` | Дата начала действия курса из XML; для RUB — дата расчёта |
| `requested_date` | Дата расчёта, запрошенная у ЦБ; может отличаться от даты действия |
| `fetched_at` | Время получения с часовым поясом |
| `source` | `CBR` или `RUB` |

Для одного расчёта создаётся один валютный снимок на уникальную валюту, включая RUB. Между разными расчётами постоянный FX-кэш пока не используется: таблица нужна для воспроизводимости и аудита. В `calculation_trades.fx_snapshot_id` хранится ссылка на использованный снимок. Существующие `fx_rate_rub`, `fx_effective_date`, `fx_source` тоже заполняются для совместимости. История до миграции имеет `fx_snapshot_id=NULL`: неизвестное время получения не восстанавливается догадкой.

Перед транзакцией записи сервис проверяет все входные строки, читает облигационные снимки/CSV, получает валютные курсы и считает все метрики. Затем одной транзакцией сохраняет новые `instrument_snapshots`, `fx_rate_snapshots`, `calculations` и все `calculation_trades`. Ошибка любой строки не оставляет частичный расчёт или новые рыночные снимки. Создание технического пользователя демонстрационным скриптом выполняется отдельно и может сохраниться, даже если сам расчёт не удался.

## Обычный сайт и личная история

`DEMO_MODE=false` отключает старые `/api/demo/*`, но не CSV-адаптер. Учебный файл с `CSV_DATA_MODE=demo` можно рассчитывать в обычной учётной записи: это метка источника, а не обход авторизации. Для реального файла выберите `CSV_DATA_MODE=market`.

`GET /api/instruments` требует входа и возвращает каталог выбранного CSV с датами котировок и меткой источника. Он не заменяет проверку свежести при расчёте. Для Cbonds каталог не предоставляется, допускается ручной ввод ISIN. POST расчёта использует cookie сессии и CSRF. Сайт получает сохранённый результат через `GET /api/calculations/{id}`; `GET /api/calculations?limit=50&offset=0` возвращает только расчёты текущего пользователя. Поддерживается лимит 1..100. Чужой расчёт возвращает 404.

Роли и административные правила из main сохранены: обычный пользователь видит расчёты, администратор также управляет пользователями через `/api/admin/users`. Первого администратора создают командой `python -m scripts.create_user admin@example.com --admin`; пароль вводится интерактивно. Первая учётная запись обычного пользователя создаётся той же командой без `--admin`.

## API и ошибки

`POST /api/calculations` требует сессию и CSRF. `quantity` проверяется строго: `true`, `1.5` и строка `"10"` не преобразуются в целое автоматически. Допустим ненулевой знаковый BIGINT. `last_trading_date` обязателен; `client_trade_id` уникален внутри расчёта и при отсутствии генерируется сервером.

Некорректный JSON/тип поля → HTTP 422. Доменная ошибка ввода, CSV, полноты или свежести → HTTP 400 с понятным `detail`. Недоступный поставщик и ошибка курса → HTTP 503. Успех возвращает ID расчёта, строки с `market_data_source`, использованным FX и метриками, общий DV01. Демонстрационные маршруты сохраняют прежний формат для frontend.

## Cbonds

`CbondsAdapter` получает выпуск и последнюю торговую запись одного ISIN; полная цена в валюте бумаги приоритетнее чистой процентной. Неполные данные не сохраняются. Учебные файлы `tests/fixtures/cbonds_*_demo.json` содержат сокращённые ответы ограниченного DEMO-доступа по разным ISIN и не образуют полноценный снимок. Тесты успешной нормализации используют отдельные синтетические данные. Реальный доступ к Cbonds для CSV и демонстрации не нужен.

## Выгрузка MOEX и чистый интерфейс

`python -m scripts.refresh_bonds_csv` получает общую таблицу рынка и карточки выпусков ISS, выбирает 100 реально торгующихся рублёвых флоатеров, запрашивает калькулятор для трёх закреплённых fixed CNY и сохраняет CSV и файлы `.meta.json`/`.source.json`. Путь берётся из `CSV_BONDS_PATH`. Можно задать `--count` и `--output`, но параметр `--count` задаёт число флоатеров, ещё три fixed CNY добавляются отдельно; стандартный итог — 103 выпуска. Недостающие данные не синтезируются. Все ISIN проверяются общим доменным валидатором.

Цены флоатеров в активном CSV — `amount/dirty`: вычислены как `FACEVALUEONSETTLEDATE` (или текущий `FACEVALUE`, если отдельный номинал не задан) × `marketdata.LAST / 100 + securities.ACCRUEDINT`. НКД относится к реальной `SETTLEDATE`, которая может быть следующим днём T+1. Дата торгов остаётся датой котировки; дата НКД не переименовывается в дату торговли. Полная цена включает её один раз; поля НКД в нормализованной dirty-записи пусты. Аудит исходного НКД и даты доступен в `.source.json` и `quote_source`.

`COUPONFREQUENCY` берётся из карточки MOEX. В CSV не заполняются фиктивные modified duration/convexity: для floating сервис вычисляет их согласно методике проекта. Не следует представлять эти методические значения как готовые риск-параметры биржи. Для fixed используется отдельный ответ калькулятора MOEX, описанный ниже.

Контрольная сумма защищает от изменения CSV отдельно от его происхождения; `.gitattributes` сохраняет точные байты этого снимка при Git checkout. Это не криптографическая подпись биржи: исходные ответы и метаданные хранятся локально.

При `CSV_REQUIRE_MANIFEST=true` вчерашняя фактическая загрузка не проходит проверку, даже если файл прочитан сегодня. Обновляйте файл новой командой, а не редактированием дат. Проверки полноты, числа строк, хеша и даты выгрузки выполняются перед созданием снимков.

Из интерфейса удалены кнопка заполнения, надпись об учебном источнике и ручное поле торговой даты. Основные визуальные компоненты и стили восстановлены из front_rew_3. Работа с авторизацией, личной историей и обычным API остаётся подключённой; код всего frontend не является побайтовой копией статической ветки с её заглушками.

## Риск-параметры fixed CNY

Закреплены `RU000A10GEU5`, `RU000A1054W1`, `RU000A10CP52`. Данные берутся из режима TQOY: номинал и валюта расчётов CNY. Поле типа купона проверяется через `COUPON_DETAILS`, поскольку `BONDTYPE` этих бумаг имеет значение «Валютная облигация».

Открытый сервис `https://iss.moex.com/iss/apps/bondization/yieldscalculator` используется и сайтом MOEX. Передаём `secid`, `tradedate`, `calc_method=BY_PRICE_TO_MATURITY`, `calc_value=LAST` (чистая процентная цена). Проверяем совпадение выпуска, даты оценки, валюты, номинала и цены. Калькулятор должен вернуть расчёт к погашению (`SELLTYPE=MATDATE`), без оферты, с конечными числами.

`MODIFIEDDURATION` и `CONVEXITY` переносятся без самостоятельных оценок и без подстановки обычной дюрации `DURATION`. `risk_as_of_date` берётся из `TRADEDATE` ответа. `PRICEWACCINT` — полная денежная цена; `ACCINT` и его дата тоже сохраняются. При `price_type=dirty` сервис повторно НКД не прибавляет.

Дата оценки и дата расчётов калькулятора совпадают с датой котировки. Это отдельная согласованная оценка T+0; НКД T+1 из торговой таблицы флоатеров не переносится в fixed-запись. Исходные ответы и параметры запросов сохранены в `.source.json`, описание метода — в `.meta.json`.

При обычном обновлении весь набор получается заново; отсутствие хотя бы одного закреплённого fixed или полного ответа калькулятора останавливает выгрузку до записи файлов. При `--add-fixed` свежие флоатеры текущего дня сохраняются без замены, добавляются/обновляются только закреплённые fixed. Раннее время загрузки флоатеров сохраняется, время добавления fixed записывается отдельно.
