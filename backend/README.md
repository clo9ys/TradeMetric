# TradeMetric: бэкенд

FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16. Python 3.12, зависимости ставим через uv

## Установка

```
cd backend
uv sync
```

Настройки лежат в `.env` в **корне репо**, не в `backend/`. Шаблон рядом:

```
cp .env.example .env
```

Нужен запущенный Postgres. docker-compose скоро появится, а пока подойдёт любой Postgres 16, доступы к нему прописываются в `.env`

## Миграции

Все команды из `backend/`

```
uv run alembic upgrade head      # накатить всё
uv run alembic downgrade -1      # откатить последнюю
uv run alembic check             # совпадают ли модели с базой
```

Новая миграция:

```
uv run alembic revision --autogenerate --rev-id 0004 -m "describe change"
```

- номера идут по порядку: 0001, 0002, ..., в `down_revision` стоит номер предыдущей
- autogenerate предлагает изменения схемы по моделям, но результат нужно проверить вручную
- сгенерированный файл всегда читаем глазами перед коммитом

Формула DV01 выполняется в Python, SQL-функции для расчёта нет. Миграция `0003` добавляет к строке сохранённого расчёта курс, дату его действия и источник.

## Работа с базой из сервиса

Сервис получает `UnitOfWork` в конструкторе и открывает его на каждую операцию:

```python
async with self._uow as uow:
    user = await uow.users.get_by_email(email)
    ...
    await uow.commit()
```

Без `commit()` всё откатывается при выходе из блока. Репозитории внутри: `uow.users`, `uow.auth_sessions`, `uow.snapshots`, `uow.calculations`

## Нормализованные данные облигации

Оба адаптера возвращают `NormalizedBondData` из `app/domain/market_data.py`. Модель проверяет полноту до сохранения в БД. Все денежные и риск-величины передаются как `Decimal`, без `float`:

- `nominal_per_bond` и `accrued_per_bond` — деньги в валюте облигации за одну бумагу;
- `quote_value` — процент непогашенного номинала при `quote_kind=percent` или деньги в валюте облигации за одну бумагу при `quote_kind=amount`;
- `price_type=clean` требует НКД и его дату, `dirty` не прибавляет НКД повторно;
- `modified_duration`, `convexity` для фиксированного купона обязательны оба параметра и дата риска;
- для плавающего купона нужна `coupon_frequency` — число выплат в год; при расчёте дюрация заменяется на `1 / coupon_frequency`, выпуклость — на ноль;
- `quote_as_of_date`, `risk_as_of_date`, `accrued_as_of_date` и `fetched_at` сохраняются раздельно.

Принятое правило свежести: котировка и риск-параметры фиксированного купона должны относиться к переданному последнему торговому дню. Сервис передаёт эту дату в `validate_freshness`; модель не определяет торговый календарь сама. Дата НКД не может быть позже даты расчёта. Повторное использование снимка, загруженного в день расчёта по Москве, реализовано отдельно в сервисе кэша.

## Адаптер Cbonds

`CbondsAdapter` реализует `BondDataProvider.get_bond(isin)` и возвращает только полный `NormalizedBondData`. Настройки доступа — `CBONDS_LOGIN`, `CBONDS_PASSWORD` и `PROVIDER_TIMEOUT_SECONDS` в корневом `.env`; секреты не помещают в код или fixture. Создание адаптера: `CbondsAdapter.from_settings(settings)`.

Cbonds запрашивает `get_emissions` и отсортированный по дате `get_tradings` для одного ISIN. Он не объединяет записи разных выпусков или разных торговых строк. При наличии полной цены берёт её в валюте бумаги за одну облигацию, не добавляя НКД ещё раз; иначе использует чистую цену в процентах и НКД из той же строки. Ошибки HTTP и таймауты отличает от отсутствующего ISIN и неполного ответа. Проверка свежести по последнему торговому дню выполняется отдельно после получения снимка.

`tests/fixtures/cbonds_*_demo.json` содержат сокращённые реальные ответы ограниченного DEMO-доступа Cbonds: выпуск и торги относятся к **разным ISIN**, поэтому не служат полноценным рыночным снимком. Успешная нормализация и HTTP-цепочка тестируются отдельно на **синтетическом** полном наборе. Адаптер RuData пока не реализован; при ошибке Cbonds автоматического перехода на него нет.

## Кэш рыночных данных

`MarketDataService.resolve_snapshots(isins, calculation_date=..., last_trading_date=...)` возвращает словарь `ISIN → InstrumentSnapshot`. Повторяющийся ISIN в одном вызове проверяется и загружается только один раз; каждая строка сделки позже может ссылаться на тот же `snapshot_id`, оставаясь отдельной строкой расчёта.

Репозиторий ищет снимки, у которых `fetched_at` приходится на дату расчёта в часовом поясе `Europe/Moscow`. Сервис повторно проверяет каждый найденный снимок через `NormalizedBondData.validate_freshness`; неполный или устаревший снимок не используется. Если пригодного снимка нет, сервис вызывает Cbonds, проверяет ответ, сохраняет новый снимок отдельной короткой транзакцией и возвращает его. Внешний HTTP-запрос не выполняется внутри транзакции БД.

Для расчёта нескольких строк используется `MarketDataService.prepare_snapshots(...)`: он получает данные до транзакции, но не сохраняет новые снимки. `CalculationService` записывает их вместе с расчётом и строками в одной транзакции; при ошибке всё откатывается. `last_trading_date` должен передать вызывающий код. Ошибка Cbonds или устаревший ответ передаются вызывающему коду.

## Расчёт DV01

`CalculationService.calculate(user_id, trades, last_trading_date=...)` принимает набор `TradeRequest` с `client_trade_id`, ISIN и ненулевым целым `quantity`. Положительное количество означает длинную позицию, отрицательное — шорт. Повторный ISIN использует один снимок, но каждая строка сохраняется отдельно. Сервис проверяет ввод, получает снимки и курсы до транзакции, затем атомарно сохраняет новые снимки, `Calculation` и `CalculationTrade`.

Формула находится в `app/services/calculation.py`, функция `calculate_trade_metrics`. Для чистой цены она добавляет НКД один раз; для грязной — не добавляет. Стоимость позиции в рублях равна `quantity × dirty_price_per_bond × fx_rate`. Для фиксированного купона берутся модифицированная дюрация и выпуклость из снимка; для флоатера используются `1 / coupon_frequency` и `0`. DV01 строки равен `CurrentFairValueRUB × (−DurationMod × 0.0001 + 0.5 × Convexity × 0.0001²)`. Общий DV01 — алгебраическая сумма строк без промежуточного округления.

Для RUB курс равен 1. Для других валют `CBRRateAdapter` запрашивает официальный курс Банка России на дату расчёта через XML-сервис и сохраняет применённые курс, дату действия и источник в строке расчёта. Снимок по ISIN должен быть получен в день расчёта по Москве и пройти проверку свежести. История расчётов затем читается из БД без новых запросов к поставщикам.
