# TradeMetric

Backend для расчёта DV01 портфеля облигаций. Стек: Python 3.12+, FastAPI, PostgreSQL 16, SQLAlchemy async, Alembic, httpx. Формула выполняется в Python с `Decimal`.

Вход — несколько строк `{isin, quantity}`. Количество — ненулевое целое со знаком: отрицательное означает шорт. Повторяющийся ISIN загружается один раз, но строки сохраняются раздельно. Итоговый DV01 — алгебраическая сумма строк.

Данные облигаций поступают из CSV либо Cbonds через один `BondDataProvider`. RuData и автоматический fallback не реализованы. Активный CSV содержит 103 реальных выпуска MOEX ISS: 100 рублёвых флоатеров и 3 fixed-облигации в CNY, источник `csv`. Валюты пересчитываются по курсу Банка России; для RUB используется 1 без HTTP.

## Установка

Все команды ниже — PowerShell. Для установки зависимостей нужен `uv` (`python -m pip install uv`, если его нет), для PostgreSQL — запущенный Docker Desktop.

```powershell
Set-Location C:\Users\MSI\Study_2nd_course\TradeMetric
# Только если .env ещё нет; существующий файл не перезаписывайте.
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Задайте POSTGRES_PASSWORD в .env до первого создания БД.
Set-Location backend
uv sync --locked
```

`uv sync` создаёт окружение `backend/.venv`. Если зависимости уже установлены в корневой `.venv`, вместо `uv run` можно выполнять `..\.venv\Scripts\python.exe -m`: например `..\.venv\Scripts\python.exe -m pytest tests/unit -q`.

## Запуск сайта

Корневой `.env` уже используется приложением. Активные настройки: `DEMO_MODE=false`, `BOND_DATA_SOURCE=csv`, `CSV_DATA_MODE=market`, `CSV_BONDS_PATH=backend/data/bonds_market.csv`, `CSV_REQUIRE_MANIFEST=true`. Пароли и реквизиты БД остаются в вашем `.env`.

В первом терминале PowerShell из корня проекта:

```powershell
docker compose up -d db
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Во втором терминале из корня:

```powershell
cd frontend
npm run dev
```

При первой установке frontend выполните `npm ci`. Нужен Node.js 20.19+ либо 22.12+. Адрес: [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Войдите в свою учётную запись, введите ISIN и ненулевое целое количество, нажмите **«Рассчитать»**. Название, таблица, кнопки и стили страницы основаны на `origin/remotes/origin/front_rew_3`; добавленные ранее метка источника, поле даты и кнопка заполнения убраны. Авторизация и работа с backend подключены отдельно от оформления.

Если учётной записи нет, из `backend` создайте её один раз:

```powershell
..\.venv\Scripts\python.exe -m scripts.create_user your.name@example.com
```

Пароль вводится интерактивно. Миграция `0005` добавляет роли, `0006` — валютные снимки. Окружение с установленными зависимостями находится в корневой `.venv`; одноимённое окружение `backend/.venv` может содержать другой Python.

## Реальные рыночные данные

[bonds_market.csv](backend/data/bonds_market.csv) содержит **103 уникальных настоящих ISIN**: 100 рублёвых флоатеров и три fixed-выпуска CNY — `RU000A10GEU5` (ФосАгро БО-03-03), `RU000A1054W1` (Полюс ПБО-02), `RU000A10CP52` (Газпром капитал БО-003Р-19). Рублёвый набор отбирается по обороту, эти три валютных выпуска закреплены и обновляются при каждом запуске скрипта. Неизвестные цены и риск-параметры не генерируются.

Первый снимок получен **19.11.2026 в 11:25:56 МСК**, дата торгов — **19.11.2026**. Для проверки можно ввести:

| ISIN | Выпуск |
|---|---|
| `RU000A0JV4N8` | ОФЗ-ПК 29009 |
| `RU000A10GL37` | Газпром капитал БО-003Р-31 |
| `RU000A10GHB8` | Атомэнергопром 001Р-19 |

CSV читается для пользовательского запроса через прежний `CsvBondDataProvider`; на каждую сделку используется только её ISIN. Метаданные списка позволяют автоматически сопоставить имя выпуска, валюту и эмитента. Дата котировки передаётся в API из файла, в интерфейсе служебного поля даты нет.

Рядом находятся [метаданные выгрузки](backend/data/bonds_market.meta.json) и [исходные записи MOEX](backend/data/bonds_market.source.json). В них сохранены дата торгов, реальное время загрузки, контрольная сумма CSV, исходные цены, НКД, дата расчётов и частоты выплат из карточек биржи. Источник: [MOEX ISS](https://www.moex.com/a2193), [справочник методов](https://iss.moex.com/iss/reference/).

Полная цена **рассчитана из фактических полей MOEX**, а не опубликована как отдельная котировка: `nominal_on_settlement × LAST / 100 + ACCRUEDINT`. При расчётах T+1 НКД относится к `SETTLEDATE` (для первой выгрузки — 20.11.2026). Поэтому в CSV записана уже полная цена `amount/dirty`, НКД повторно не прибавляется; исходная дата НКД не подменяется 19.11.2026. Частота купонов взята из `COUPONFREQUENCY` карточки, без приблизительного округления периода. Дюрация флоатера `1/frequency`, выпуклость `0` — правила TradeMetric, не публикуемые биржей риск-параметры.


Для трёх **fixed CNY** дюрация и выпуклость получены через публичный запрос [калькулятора MOEX](https://www.moex.com/ru/bondization/calc): `/iss/apps/bondization/yieldscalculator`, метод `BY_PRICE_TO_MATURITY`, дата = дата рыночной котировки, цена = `LAST` выбранного режима TQOY. В CSV переносятся `MODIFIEDDURATION` (годы), `CONVEXITY` (годы²), `PRICEWACCINT` (полная цена CNY) и `ACCINT` (НКД CNY) **из одного ответа**. Обычная дюрация `DURATION` не подставляется вместо модифицированной.

Калькулятор оценивает эти цены и риски на переданную дату (`TRADEDATE=SETTLEDATE=19.11.2026` в добавленном снимке). Для fixed не смешивается НКД торговой таблицы на T+1 с риском на текущую дату. Полная цена уже включает НКД; отдельная сумма и дата НКД также сохранены для проверки и повторно в цену не добавляются. Точный запрос, параметры, ответ и исходная котировка лежат в `.source.json`.

Первое добавление fixed выполнено 19.11.2026 в 11:56 МСК. Исходные 100 флоатеров сохранены без переотбора; их время загрузки осталось 11:25 МСК. Метаданные отдельно содержат `floating_downloaded_at`, `updated_at` и самое раннее `downloaded_at`. Опция `--add-fixed` позволяет обновить только эти три fixed в свежем CSV того же дня; обычный запуск обновляет весь набор из 103 бумаг.

В следующий день обновите выгрузку из `backend`:

```powershell
..\.venv\Scripts\python.exe -m scripts.refresh_bonds_csv
```

Команда запрашивает реальные данные MOEX и обновляет 100 флоатеров и три закреплённых fixed CNY, даты, исходные ответы и контрольную сумму. Если полного набора или корректных рисков калькулятора нет, старый CSV остаётся без изменений. Рыночный файл, загруженный в другой московский день, отклоняется до расчёта: повторное чтение не делает его свежим. Даты не переписываются для обхода проверки. В неторговые часы/дни наличие 100 пригодных записей зависит от ответа биржи; историческая дата не выдаётся за текущие торги.

## API и другие режимы

[Swagger UI](http://127.0.0.1:8000/docs), [проверка БД](http://127.0.0.1:8000/api/health).

Обычный сайт использует `GET /api/instruments`, `POST /api/calculations`, `GET /api/calculations` и `GET /api/calculations/{id}`. Все требуют входа, POST дополнительно требует CSRF; frontend передаёт его через общий API-клиент. История и отдельный расчёт доступны только их владельцу. Изменение URL не позволяет прочитать чужой расчёт.

```json
{
  "last_trading_date": "2026-11-19",
  "trades": [
    {"isin": "RUDEMO000016", "quantity": 10},
    {"isin": "RUDEMO000016", "quantity": -2},
    {"isin": "RUDEMO000032", "quantity": 7}
  ]
}
```

Для позднейшего Cbonds задайте `BOND_DATA_SOURCE=cbonds`, `CBONDS_LOGIN`, `CBONDS_PASSWORD`. Его список бумаг через CSV-каталог не выдаётся; ISIN вводятся вручную. Автоматического fallback нет.

Дополнительный CLI-сценарий синтетических данных остаётся доступен при выборе CSV/demo:

```powershell
# Из backend; это создаёт отдельного технического пользователя и один расчёт.
..\.venv\Scripts\python.exe -m scripts.demo_calculation --last-trading-date 2026-11-19
```

Для обычного сайта этот скрипт **не нужен**. Старые `/api/demo/*` включаются отдельно через `DEMO_MODE=true` и `DEMO_LAST_TRADING_DATE=2026-11-19`; текущий сайт к ним больше не обращается.

## Проверка ЦБ и тесты

Из `backend`:

```powershell
# Реальный внешний запрос без записи в БД:
uv run python -m scripts.check_cbr USD --date 2026-11-19
uv run python -m scripts.check_cbr CNY --date 2026-11-19
# RUB не вызывает внешний сервис:
uv run python -m scripts.check_cbr RUB --date 2026-11-19
uv run pytest tests/unit -q
```

Для полного набора с PostgreSQL последовательно выполните:

```powershell
# Из корня:
docker compose up -d db
docker compose ps
Set-Location backend
# Читает реквизиты из .env без печати пароля. Для локального Docker используем IPv4.
$env:TEST_DATABASE_URL = uv run python -c "from app.config import get_settings; print(get_settings().database_url.set(host='127.0.0.1').render_as_string(hide_password=False))"
uv run pytest -q
Remove-Item Env:TEST_DATABASE_URL
```

Интеграционные тесты накатывают миграции в отдельных случайных схемах `dv01_test_*`, проверяют сохранение и откат, затем удаляют только свои схемы. Пользовательские таблицы не очищаются. Без `TEST_DATABASE_URL` эти тесты пропускаются. Проверка соответствия моделей миграциям также входит в набор. Ответы ЦБ в тестах подменены через `httpx.MockTransport`; реальный запрос выполняет отдельный `check_cbr`.

Описание всех CSV-колонок, правил дат, формулы и хранения — в [backend/README.md](backend/README.md). Разбор пути данных и синтаксиса для начинающего — в [docs/data-flow.md](docs/data-flow.md).
